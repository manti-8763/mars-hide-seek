# 세 기기 화면과 연결

프로젝트 문서 `탐사_인터페이스_설계.md`의 설계를 구현한 것입니다. 우주비행사가 쓰는 기기 둘(헬멧 HUD, 손목·태블릿)과 기지 상황판이 각각 다른 기기에서 따로 열립니다.

## 1. 기기별 화면

### 헬멧 HUD — [hud.html](../hud.html)

바로 조작할 수 없는 기기라서 원래 시야를 가리지 않도록 가장자리에 최소한만 표시합니다. 3D 지형은 실제로 헬멧 너머로 보일 풍경을 대신합니다.

| 위치 | 내용 |
|---|---|
| 지형 위 | 지형 표시 한 가지 (서로 겹치므로 하나만): **없음 / 전파도달도 / 중계기 전파도** |
| 위 가운데 | 지금 링크 마진과 경유 노드. 그 아래에 중계기 설치 확인 메시지. 600 m 안에 끊김이 있거나 400 m 안에 중계기 설치 지점이 있으면 둘째 줄에 표시 |
| 위 오른쪽 | 지금 지형 표시, 손목 기기 연결 상태 |
| 아래 | 단면 띠 (켜고 끄기): 착륙선, 가까운 놓인 중계기 2대, EVA 목표까지 |
| 아래 왼쪽 | 지형 표시의 범례. 중계기 전파도일 때는 그 자리 중계기의 착륙선까지 마진 |
| 라벨 | 착륙선·중계기·목표의 이름과 거리 |

- **전파도달도**: 지금 놓인 중계기로 각 지점에 서면 착륙선과 이어지는지(초록 안정, 노랑 불안정, 빨강 끊김). 주변 반폭 3 km를 24 m 격자로 계산합니다.
- **중계기 전파도**: 지금 서 있는 자리에 중계기를 놓으면 새로 닿는 곳(진한 청록)과 안정해지는 곳(옅은 청록). 계산 방법은 [network-and-optimizer.md](network-and-optimizer.md) 2절.
- **조작**: 손목 기기 없이도 쓸 수 있도록 우주복 버튼 3개를 가정합니다. 화면 오른쪽 아래의 같은 버튼을 눌러도 됩니다. 바꿀 때 애니메이션은 없습니다.
  - 버튼 1 (키 `1`): 지형 표시를 없음 → 전파도달도 → 중계기 전파도 순서로 바꿉니다.
  - 버튼 2 (키 `2`): 단면 띠를 켜고 끕니다.
  - 버튼 3 (키 `3`): 지금 서 있는 자리에 중계기를 놓습니다. 실수로 놓지 않도록 두 번 누릅니다. 첫 번째 누름은 상태 줄 아래에 "여기에 놓으면 착륙선까지 +n dB"(지금 놓인 중계망을 거친 경로의 병목)를 보여 주고, 4초 안에 다시 누르면 설치합니다. 그 자리에서 착륙선과 이어지지 않으면 경고를 보여 주지만 두 번째 누름으로 놓을 수는 있습니다. 놓은 중계기는 계획에 더해지고 손목·기지로 전달됩니다. "중계기 전파도"를 켜 두면 놓기 전에 새로 닿을 곳을 볼 수 있습니다.
- 손목 기기와 연결되어 있으면 손목에서 고른 표시가 바로 반영되고, 헬멧에서 바꾼 것도 손목에 반영됩니다.

### 손목 · 태블릿 — [tablet.html](../tablet.html)

복잡한 조작이 어려우므로 모든 정보와 조작을 한 화면에 두고, 조작은 버튼과 스와이프(지도 회전·확대)로만 합니다. 글자 입력과 슬라이더는 없습니다.

| 영역 | 내용 |
|---|---|
| 위 막대 | 지금 링크 마진·경유, 걸은 거리 / 전체 · sol, 헬멧·기지 연결 상태 |
| 지도 | 주변 3D 지도(전파도달도), 라벨에 거리. "내 위치", "전체" 버튼 |
| 헬멧 표시 | 지형 표시 버튼 3개(없음 / 전파도달도 / 중계기 전파도), 단면 그래프 켜고 끄기 버튼 1개 |
| 수치 | 남은 경로 통신 유지 %, 다음 끊김, 다음 중계기 설치, 설치한 중계기, 남은 거리, 지금 통신 가능 면적 |
| 중계기 | 새로 놓을 개수(−/+), 자동 배치 계산, 여기에 설치 |
| 기지 동기화 | 켜기/끄기 (기본은 꺼짐) |
| 아래 | EVA 경로의 링크 마진 타임라인 |
| 시뮬레이션 (시연용) | 걷기/멈춤, 처음으로, 속도, 헬멧 연결 끊어 보기 |

- **헬멧이 끊기면**: "헬멧 표시" 칸이 빨갛게 바뀌고, 헬멧에서 보였어야 할 것을 이 화면이 대신 보여 줍니다. 지도의 지형 표시가 헬멧에서 고른 것을 따르고, 단면 띠가 아래에 나타납니다. 연결되어 있을 때 지도는 항상 전파도달도입니다.
- **자동 배치**: 설치 위치는 EVA 경로 근처, 후보 간격 200 m입니다. EVA 도중에 실행하면 이미 놓은 중계기는 그대로 두고 남은 경로만 다시 계획합니다.
- **여기에 설치**: 지금 위치에 중계기를 하나 놓고 계획에 더합니다.
- 세로로 긴 화면(손목 기기, 휴대폰)에서는 위에서 아래로 쌓이고, 조작 칸만 따로 스크롤됩니다.

### 기지 상황판 — [base.html](../base.html)

착륙선·기지·지구에서 보는 전체 상황판입니다. 계산이 많은 시뮬레이션과 모든 설정이 여기 있습니다.

| 영역 | 내용 |
|---|---|
| 위 막대 | 현장 동기화 상태, 계획 보내기 |
| 왼쪽 (탭 하나씩) | 배치: 자동 배치 옵션 전체, 직접 놓기 · 무선: 방식과 값, 안테나 높이, 요구 마진 · EVA: sol 범위, 설치 시점, 경로 재생 · 표시: 도달 지도 격자·투명도, 수직 과장, 텍스처, 출처 |
| 가운데 | 3D 지도(계획한 중계기 전체 기준 도달 지도), 보기·착륙선·중계기·삭제 도구 |
| 오른쪽 | 현장 카드(마진, 경유, 위치, 설치 수, 헬멧 표시), 요약 수치, 노드 목록 |
| 아래 | 그래프 하나: EVA 타임라인 / 링크 단면 / 커버리지 분포 |

- 기지에서 바꾼 계획은 바로 현장에 가지 않습니다. "현장에 계획 보내기"를 눌러야 보냅니다. 보내지 않은 변경이 있으면 위 막대에 표시됩니다.
- 현장 계획이 바뀌어 들어왔을 때, 기지에 보내지 않은 변경이 없으면 그대로 받아들이고, 있으면 "현장 계획 불러오기" 버튼을 띄웁니다.
- 현장과 동기화 중에는 EVA 위치가 현장을 따라가고, 기지의 경로 재생 버튼은 잠깁니다.

## 2. 혼자 동작하기

설계 문서의 전제대로 세 화면은 모두 연결 없이 동작합니다.

- 각 화면이 지형·경로 데이터와 계산 코드를 모두 갖고 있고, 계산도 자기 기기에서 합니다.
- 우주비행사의 위치는 시뮬레이션에서 EVA 경로를 따라 걷는 것으로 대신합니다. 각 기기가 자기 시계로 걷기 때문에 연결이 끊겨도 위치가 계속 움직이고, 다시 연결되면 맞춰집니다.

## 3. 연결 — [js/link.js](../js/link.js)

기기들이 주고받는 상태는 세 묶음입니다([js/core/plan.js](../js/core/plan.js)).

| 묶음 | 내용 |
|---|---|
| `plan` | 착륙선, 중계기, 무선 설정, 안테나 높이, 요구 마진, EVA sol 범위, 설치 시점 |
| `walk` | 경로 위 위치(m), 걷는 중인지, 속도 |
| `hud` | 헬멧 지형 표시, 단면 켜짐 |

| 범위 | 기기 | 보내는 것 | 받는 것 |
|---|---|---|---|
| `crew` (보통 항상 연결) | 헬멧 ↔ 손목 | 세 묶음 모두 | 세 묶음 모두 |
| `base` (손목에서 켰을 때만) | 손목 → 기지 | 세 묶음 모두 | — |
| | 기지 → 손목 | `plan` (보낸 계획) | 손목은 `plan`만 받음 |

- **누가 이기나**: 묶음마다 Lamport 타임스탬프 `[카운터, 기기 id]`가 붙습니다. 기기에서 그 묶음을 바꾸면 카운터를 올리고, 받은 값이 자기 것보다 새로울 때만 받아들입니다(나중에 쓴 쪽이 이김).
- **다시 맞추기**: 모든 기기가 1초마다 자기 묶음을 다시 보냅니다. 끊겼다가 돌아오거나 새로 고친 기기도 곧 맞춰집니다. 헬멧도 `plan`을 보내기 때문에, 손목 기기를 새로 고쳐도 헬멧에 남아 있던 계획을 되찾습니다.
- **연결 상태**: 상대 기기에서 3.5초 동안 아무것도 오지 않으면 끊긴 것으로 봅니다. 끊겼던 상대에게서 다시 소식이 오면 곧바로 답을 보내서 양쪽이 동시에 연결을 알아챕니다.
- **기지 동기화는 우주비행사 쪽에서 켭니다**: 손목에서 켜지 않으면 손목은 `base` 범위로 보내지도 받지도 않습니다.

### 전송 경로

| 경로 | 범위 | 언제 |
|---|---|---|
| 중계 서버 (`serve.py`의 `/bus`) | 같은 네트워크의 다른 기기 | `serve.py`로 열었을 때. `POST /bus`로 보내면 `GET /bus`(Server-Sent Events)로 듣는 모든 기기에 전달 |
| BroadcastChannel | 같은 브라우저의 탭·창 | 항상 (정적 호스팅에서도) |

두 경로를 함께 쓰고, 같은 메시지가 두 번 와도 타임스탬프 비교로 한 번만 반영됩니다. 중계 서버는 메시지를 저장하지 않고 전달만 합니다. 메시지 하나는 256 KB 이하의 JSON이어야 합니다.

## 4. 다른 기기에서 열기

```bash
python serve.py --lan
```

서버가 이 컴퓨터의 네트워크 주소를 출력합니다(시작 화면에도 나옵니다). 같은 네트워크의 휴대폰·태블릿에서 그 주소를 열고 화면을 고릅니다. `--lan` 없이 실행하면 이 컴퓨터에서만 열립니다.

- `--lan`이면 같은 네트워크의 누구나 페이지를 열고 메시지를 보낼 수 있습니다. 믿을 수 있는 네트워크에서만 쓰세요.
- Windows에서는 처음 `--lan`으로 실행할 때 방화벽이 Python의 네트워크 접근을 물을 수 있습니다.
- three.js를 CDN에서 받으므로 각 기기에 인터넷 연결이 필요합니다.

## 5. 시연 순서 예

1. 한 컴퓨터에서 `python serve.py`를 실행하고 `hud.html`, `tablet.html`, `base.html`을 각각 다른 창으로 엽니다.
2. 손목에서 "자동 배치 계산" → 헬멧과 손목에 중계기 계획(R1…)이 나타납니다.
3. 손목에서 "▶ 걷기" → 헬멧 시점이 경로를 따라 움직입니다. 중계기 설치 지점을 지나면 헬멧의 전파도달도가 넓어집니다.
4. 헬멧에서 키 `1`을 눌러 "중계기 전파도" → 지금 자리에 중계기를 놓으면 새로 닿는 곳이 보입니다. 키 `3`을 두 번 누르면 그 자리에 중계기를 놓고, 손목 화면의 설치 수가 늘어납니다.
5. 손목의 "헬멧 연결 끊어 보기" → 손목이 헬멧 내용을 대신 보여 주고, 헬멧은 혼자 계속 걷습니다.
6. 손목에서 "기지 동기화 켜기" → 상황판에 현장 위치와 설치 상황이 나옵니다. 상황판에서 요구 마진을 바꾸고 "현장에 계획 보내기" → 손목과 헬멧에 반영됩니다.
