# 구조 — 모듈, 데이터 흐름, 렌더링

웹 시뮬레이터는 빌드 단계가 없는 정적 페이지입니다. 브라우저가 ES 모듈을 직접 불러오고, three.js r160은 import map을 통해 CDN(cdn.jsdelivr.net)에서 받습니다.

화면은 기기별로 셋입니다(헬멧 HUD, 손목·태블릿, 기지 상황판). 세 화면은 같은 계산 코드(`js/core/`)를 쓰고, 각자 독립적으로 동작합니다. 화면 설계와 기기 사이 연결은 [devices.md](devices.md)에 있습니다.

| 파일 | 내용 |
|---|---|
| `boot.js` | 시작 순서와 기기별 링크 설정 |
| `dom.js` | 분할 버튼, 켜고 끄기 버튼, ± 단추, 설정 입력, 진행 표시, 숫자 표기 |
| `charts.js` | EVA 타임라인, 링크 단면, 커버리지 분포, 단면 띠 |

`physics.js`는 메인 스레드와 워커가 함께 씁니다. 그래서 화면에 보이는 링크 하나의 값과 지도의 값이 같은 코드에서 나옵니다.

## 2. 시작 순서 (`boot()`)

1. 페이지가 `S.ui`의 기기별 값(격자 간격, 도달 지도 범위와 기준 망, 지형 표시)을 정합니다.
2. `load()`: `data/meta.json`, 지형 격자, `data/route.json`, `data/ortho_4m.jpg`를 동시에 불러오고 워커 풀을 만듭니다.
3. `scene.build(img, {firstPerson})`: 렌더러, 카메라, 지형 메시, 텍스처를 만듭니다. 헬멧은 1인칭입니다.
4. `defaultScenario()`: EVA 구간 sol 2691–4293, 착륙선은 구간 시작점, 중계기 없음.
5. 워커가 준비되면 `recompute()`와 `moveEva(0)`을 실행합니다.
6. 링크(`createLink`)를 만듭니다. 헬멧과 손목에서는 계획이 바뀔 때마다(`'net'`, `'radio'`, `'eva'`, `'plan'` 이벤트 뒤 계획 JSON이 달라졌을 때) 자동으로 새 타임스탬프를 붙입니다. 기지는 "현장에 계획 보내기"를 눌렀을 때만 붙입니다.

디버깅용으로 각 화면은 `window.__sim = { S, A, bus, link }`를 열어 둡니다.

## 3. 상태 `S`와 이벤트

| 필드 | 내용 |
|---|---|
| `device` | `'hud'`, `'tablet'`, `'base'` |
| `meta`, `T`, `route`, `W`, `H`, `zRef` | 메타데이터, 지형 객체, 경로, 지형 폭·높이(m), 기준 고도 |
| `nodes` | `{id, type: 'lander'|'relay', x, y, name}`. 착륙선은 항상 0번 |
| `radio`, `R`, `h`, `req` | 무선 설정과 계산된 상수, 안테나 높이, 요구 페이드 마진 |
| `net` | 계획 전체 중계망 `{infra, mat, best, prev}` |
| `now` | 지금 놓인 중계기만의 망 `{on[], best, prev, count}` |
| `cov` | 도달 지도 `{stride, c0, r0, cw, ch, perNode[], comb, landerOnly, net, cx, cy, half}` |
| `preview` | 중계기 전파도 `{stride, c0, r0, cw, ch, m, bb, x, y}` |
| `eva` | 경로 표본, 표본별 마진·경유 노드·착륙선 직결 마진, 설치 거리, 재생 위치 |
| `hud` | 헬멧 표시 `{mode: 'none'|'reach'|'relay', info}` |
| `ui` | 화면 설정: 격자(`covStride`), 범위(`covWin`), 기준 망(`covNet`), 자동 배치(`opt`), EVA(`eva`), 표시(`display`) |

모듈끼리 직접 부르지 않고 `A.*`(동작)와 `bus`(이벤트)로 이어집니다. 주요 이벤트:

| 이벤트 | 언제 |
|---|---|
| `net` | 계획 중계망을 다시 계산함 |
| `now` | 지금 놓인 중계기 집합이 바뀜 |
| `eva`, `evaPos`, `evaState` | EVA 다시 계산 / 위치 이동 / 재생·멈춤 |
| `cov`, `preview` | 도달 지도 / 중계기 전파도 계산 끝 |
| `profile`, `strips` | 선택 링크 단면 / 단면 띠 계산 끝 |
| `hud` | 헬멧 표시가 바뀜(직접 또는 다른 기기에서) |
| `plan`, `ui` | 계획을 이 기기에서 바꿈 / 다른 기기의 계획을 받아 설정이 바뀜 |
| `busy` | 진행 표시 |

## 4. 갱신 흐름

```
recompute()
 ├─ 착륙선+중계기 모든 쌍의 링크 마진 → widestPath()로 백본 트리 → 'net'
 ├─ computeEva()     EVA 표본별 마진, 설치 거리 → 'eva'
 ├─ computeNow()     지금 놓인 중계망 → 'now' (바뀌었을 때만)
 ├─ updateProfile()  선택 링크의 단면과 Fresnel 타원체
 └─ scheduleCoverage()  250 ms 뒤 도달 지도
moveEva()  (재생 중 매 프레임)
 ├─ computeNow()        중계기 설치 지점을 지나면 'now' → 도달 지도 다시 계산
 └─ coverageFollows()   창 방식이면 창 밖으로 나갈 때 다시 계산
```

## 5. 워커 풀

`Pool`은 `navigator.hardwareConcurrency − 1`개(최소 2, 최대 8)의 모듈 워커를 띄웁니다. `pool.run(messages, onProgress)`는 메시지를 쉬는 워커에 나눠 주고 결과를 입력 순서대로 돌려줍니다. 결과 배열은 transferable로 넘깁니다. 도달 지도와 미리보기는 요청 번호로 오래된 결과를 버립니다. 메시지 형식은 [network-and-optimizer.md](network-and-optimizer.md) 5절에 있습니다.

## 6. 3D 렌더링

**좌표 변환**: 지형 로컬 좌표 (x 동쪽, y 남쪽, m)를 three.js 좌표로 바꿉니다. X = x − W/2, Y = (z − zRef) × 수직과장, Z = y − H/2.

**두 카메라**

| | 내려다보기 (손목, 기지) | 1인칭 (헬멧) |
|---|---|---|
| 조작 | OrbitControls (끌기·두 손가락) | 끌어서 고개 돌리기, 더블클릭으로 정면 |
| 위치 | 사용자가 정함. `focus(x, y, 거리)`, `focusAll()`로 부드럽게 이동 | EVA 현재 위치, 눈높이 = 지형 + 우주비행사 안테나 높이 + 0.2 m |
| 방향 | — | 경로를 60 m 앞까지 본 방향. 경로가 꺾이면 천천히 따라 돎 |
| 수직 과장 | 1.5 (설정 가능) | 1 (실제 높이) |
| 마커 | 표시용 큰 기호 (약 80 m) | 실제 크기 (마스트 약 3.5 m). 거리는 라벨로 보임 |
| 하늘 | 어두운 배경 | 먼지 낀 하늘색과 안개(4–30 km) |

1인칭 눈높이는 메시(16 m 정점)의 높이와 8 m 격자 높이 중 큰 값을 씁니다. 메시가 격자보다 높은 곳에서 눈이 지면 아래로 들어가지 않게 하기 위해서입니다.

**장면 구성**: `exGroup`(지형 메시, 링크 선, Fresnel 타원체 — 그룹의 `scale.y`로 과장)과 `flatGroup`(노드 마커, EVA 마커 — 위치에만 과장을 곱함)으로 나뉩니다. 1인칭에서는 링크 선과 EVA 마커를 그리지 않습니다.

**텍스처** (`composeTexture()`): 캔버스 하나에 합성합니다.
1. 바탕: HiRISE 정사영상에 화성색 틴트, 또는 고도 색상과 음영
2. 지형 표시(`S.ui.display.overlay`): `'reach'`면 도달 지도 색, `'relay'`면 중계기 전파도(청록), `'none'`이면 없음. 창 방식 격자는 창 위치에 맞춰 그립니다. 헬멧은 칸 경계를 부드럽게(보간) 그립니다.
3. EVA 경로. 기지에서 설치 위치가 "EVA 경로 근처"이면 후보 범위를 파란 띠로 그립니다.

**라벨**: HTML 요소로 그리고 매 프레임 화면 좌표로 옮깁니다. 글자는 초당 4번 바꿉니다. 헬멧과 손목은 라벨에 우주비행사로부터의 거리를 붙이고, 아직 놓지 않은 중계기는 점선 테두리로 "예정"이라고 표시합니다. 노드가 아닌 지점(EVA 목표)은 `setPois()`로 붙입니다.

## 7. 지형 클릭 (기지)

three.js의 메시 레이캐스트는 느려서 `pick()`이 높이장을 직접 따라갑니다. 카메라 광선을 12 m부터 점점 넓은 간격으로 전진시켜 지형 아래로 들어가는 첫 지점을 찾고, 그 구간을 20번 이분합니다. 누른 위치와 뗀 위치가 4 px 이내일 때만 클릭으로 봅니다.

## 8. 그래프 (`js/ui/charts.js`)

모두 2D 캔버스에 직접 그립니다. 눈금 간격은 `niceStep()`이 1·2·5 × 10ⁿ 중에서 고릅니다.

- **EVA 타임라인**: 가로는 걸은 거리, 세로는 마진(−30 ~ 40 dB로 자름). 색 막대는 중계망, 회색 선은 착륙선 직결, 흰 선과 삼각형은 현재 위치, 파란 선은 중계기 설치 지점(점선은 아직 놓지 않음). 손목에서는 지나온 부분을 흐리게 그립니다. 기지에서는 누르면 그 지점으로 이동합니다.
- **링크 단면** (기지): 곡률 보정 지형, 가시선, Fresnel 1차·60 % 선, 회절 능선, 링크 예산 수치.
- **커버리지 분포** (기지): 칸별 마진의 5 dB 구간 비율. 막대는 중계망, 회색 선은 착륙선 단독.
- **단면 띠** (헬멧, 손목): 우주비행사에서 착륙선·가까운 중계기 2대·EVA 목표까지. 지형 실루엣, 노드까지의 가시선(가려지면 점선), 선을 따라 49점에서 계산한 도달 마진을 지면 위 색으로 그립니다.

## 9. claude.ai Artifact 게시본

이전 게시본은 한 화면짜리 이전 버전(`index.html` + `js/app.js` + `style.css`)으로 만든 것입니다. 지금 구조로 다시 게시하려면 게시 스크립트를 세 화면 구조에 맞게 고쳐야 합니다. 게시본에는 중계 서버가 없으므로 기기 사이 연결은 같은 브라우저의 탭끼리(BroadcastChannel)만 됩니다. 지형 격자는 claude.ai가 바이너리를 제공하지 않아 base64 텍스트(`data/terrain_8m_f32.b64.txt`)로 올리고, `data.js`가 `.f32`를 받지 못하면 이 사본을 씁니다.
